# Bell Theory — decision log

Live prototype: https://claude.ai/artifact/CWf9vb1oyPNrheKD119Fh5

## 2026-09-23

- **New project, not a bolt-on.** Repo `tempname` holds `loom` (ambient generative audio/visual). Unrelated domain. Prototype lives as a single HTML artifact; repo untouched so far.
- **Two sides, screen-half binding.** Left half of screen = left thumb, right half = right thumb. Touch order binding was tried first and dropped: "left thumb" should mean left. Browser Touch API cannot identify fingers; spatial binding is the honest proxy.
- **Hemi-sync / binaural tones as a mechanic: built, then killed.** Holding a mirrored pose is thin as an objective. Binaural beats also need headphones; a phone speaker collapses them. Dropped entirely.
- **Core loop = two-thumb endless vertical runner.** Dodge gaps in both lanes at once, collect coins, one-hit death, instant restart. Difficulty comes from bilateral motor interference, which is free — no need for tiny hitboxes.
- **Coordination lives in obstacle patterns, not a sync meter.** Gaps spawn mirrored / parallel / independent. Ramp weights toward independent (the hard one for a human motor system). Parallel alignment gives a ×2 coin bonus, never a requirement.
- **Audio: loom's `World` state vector ported, binaural + birds + recorder dropped.** Drone + filtered noise bed, driven by gameplay (entropy = difficulty, warmth = charge/tier/boost). Drone reweighted to 220 Hz and up: phone speakers roll off below ~200 Hz. Beds start on first touch, not run start (desktop mouse can never have two pointers).
- **Thumb occlusion:** avatar rides 62 px above the touch point on touch input only; tether line back to the finger; lane-wall ticks; mirror ghost that fades in near symmetry.
- **Pass = accomplishment.** `threaded()` fires when a barrier clears without a hit: combo, ring, floating text, gap flash, pitch-climbing blip, world ripple. CLEAN within 34 % of gap center, CLOSE just outside.
- **UI collision pass.** Top bar is one flex row (three absolute boxes were stacking on phones). Combo moved out of the scan zone into the top bar. BEST removed from the live bar. Rings shrunk 80→44. Obstacles solid slate; ripple only brightens the rim (body tint went mauve).
- **Game renamed "Bell Theory"** — Bell's theorem, not Pavlov (I misread it first). Two separated systems, a seam between them, outcomes correlated beyond what either side produces alone: left and right thumbs are the entangled pair, the parallel bonus is the correlated measurement. Title, `<title>`, and gallery updated.
- **Reward design.** Applied: variable-magnitude SURGE passes (RPE — Schultz 1997), ±30 % stroke jitter so the ignition moment is uncertain (ramping — Fiorillo 2003), coin glint + chime on screen entry (cue precedes reward — Berridge). Deliberately skipped: losable wagers, return timers, withheld rewards. Uncertainty about *how much*, never *whether*. Scope of the name (framework vs game title) still open.
- **Boost = pump.** Rhythmic vertical strokes (≥34 px) fill a tank; both thumbs within 220 ms = 1.8×. Ignites at 100, drains at 40/s, pumping during boost refills it (chainable). Rocket League gauge on the seam, bottom-center: between thumbs, never occluded, fill reads by shape in lower periphery.
- **Haptics on iPhone.** `navigator.vibrate` does not exist on iOS, and a binaural beat has no waveform to feel. But I overstated the speaker: user reports a felt chassis buzz on coin pickup at full volume, and that's real — speaker-to-frame coupling on sharp transients in the driver's reproducible band. So `thump()` is now tuned *for* coupling: lowpassed square (fundamental + odd harmonics the driver can push), pitch held in 170–240 Hz rather than sweeping below it, 4 ms attack, hotter defaults, an **Impact** slider (0–200 %, default 120) independent of bed volume, and a master compressor so hot hits duck the bed instead of clipping. Real haptics still = native wrapper → Core Haptics, but the free version is worth having.
- **Boost gauge legibility fix.** Reported as "doesn't make sense nor obvious." Causes: nothing at the gauge reacted per stroke; the ×2 coin chip was on the boost widget (two concepts, one widget); label said BOOST before the player knew how to get any. Fixes: seam is now the fill column rising from the gauge; gauge pops per stroke; label reads PUMP ↕ → BOOST → LIT; ×2 moved beside COINS; one-time in-run hint after 3 s without a stroke (`taughtPump` persisted so it never nags again).
- **Wrecking is a second playstyle, not an exploit.** User noticed pump-during-boost makes boost sustainable and that smashing is its own fun. Smash was a flat +6 with no escalation — a worse loop than threading. Now: barrier rects break into physics chunks (velocity from impact, gravity, spin, fade); a **wreck chain** escalates within each boost (points ×(1+0.25n), bigger shake, heavier thump, growing label); **CRUNCH** at 12 % is the variable-magnitude hit; each smash **refunds 8 % tank** so wrecking sustains wrecking; barriers turn **gold as they come into range** while lit (cue precedes hit); at chain 4–6 (randomized per boost) a **WRECKED storm** clears every barrier on screen into debris, flashes, +40, +25 % tank. Smashes also feed the shared combo, so mixing threading and wrecking keeps one streak alive.
- **Crash fix (v11).** WRECKED storm emptied `game.obstacles` from inside the loop iterating it → read of a missing index → TypeError → and because the rAF re-arm sat at the end of `frame()`, one throw froze the game permanently. Fixed the loop (bounds re-check per iteration) and wrapped `update()`/`draw()` in try/catch so a bad frame can never kill the loop again; frame errors now surface in the panel's Engine line so they can be reported. Also cut iOS draw cost: seam halo is a gradient instead of `shadowBlur` on a tall rect, coins use a cheap halo ring instead of blur, avatar blur capped at 34, stroke tick throttled to ≤12/s, click transient buffer shared instead of allocated per hit.
- **Title / death screen design pass (v12).** Ready screen had two paragraphs running over the orbs, a 0/0/0 scoreboard, and the gauge clipped off the bottom. Fixes: `.app` sized `100%` not `100dvh` (host pads root by safe-area; dvh overflowed it — that was the clip); overlays are positioned blocks (title at 24 %, CTA at 62 %) so text never reaches the orbs; copy removed from the title screen and moved into a collapsed **How to play** `<details>` at the top of the panel; each orb wears a breathing dashed ring on the title screen that drops when that side is touched — the orb is the instruction; stats bar hidden until a run starts; death screen restructured as label / big distance / coins+best / open-loop line / CTA, anchored in the upper fifth so it never lands on the frozen orbs.
- **First full read-through (v13) — bugs found and fixed.** Restart called `resetCursors()`, teleporting the *other* thumb's orb to lane centre and placing the new one at raw touch y instead of offset y → pop on every restart. Dying while lit left `game.boost` set, so gold rims and speed streaks kept drawing on the death screen. Trails from the previous run bled into the next. No pause on tab-hide, so a background tab could kill you. The barrier that killed you could also pay a thread bonus in the same frame. All fixed.
- **Feel layer between states (v13).** Death is now two-stage: `die()` fires the burst, red flash, crash sound and 0.55 s of 12 % slow motion (world time scaled; feedback at full rate; collisions and strokes suspended), then `finishDeath()` switches phase and fades the overlay in. Runs ease in over 1.2 s (smoothstep from 25 % speed). Overlays cross-fade instead of popping. Tab-return holds the world still for 0.8 s so you can reposition. **GRAZE**: clearing a wall with < 7 px of clearance pays +4 base, a white ring, a high blip — the near-miss beat, made explicit.
- **Steel (v14) — boost gets a difficulty.** Lit was untouchable. Now some barriers are *hardened*: crimson body, hatched, red rim that pulses as it comes into range while lit, low warning tick on entry. Boost breaks slate, not steel — hit one lit and you die ("STEEL" over the burst). Baseline 6 % so the look is learned unlit (where it behaves like any barrier); while lit the rate climbs with continuous lit time (+14 % then +5 %/s, capped +50 %), so infinite boost demands threading at ×1.85 instead of replacing it. Storms leave steel standing. Grazing steel while lit pays +10 (STEEL GRAZE).
- **One-handed mode (v14) — accessibility.** One full-width lane, one orb, any touch drives it; gap fraction tightened (34 %→16 % vs 52 %→26 %) since one gap is easier than two. Pump, boost, smash, storm, graze and steel all unchanged; parallel bonus and mirror ghost off; start needs one thumb. Persisted; toggle on the title screen (`.mode-pill`, the one overlay element with pointer-events) and in the panel; both stay in sync. Chose one-lane over "one thumb mirrored to both orbs" because the mirrored version is a one-lane game wearing two-lane clothes.
- **FINDING (v14, user play report): one-handed mode is dramatically more fun than two-handed.** First unambiguous "this is fun" of the project, and it came from the accessibility mode, not the premise. **Resolved same session: both are "really really fun."** Two first-class modes, one engine. The two-thumb premise holds; one-hand is not a fallback. Acted on (v15): the title-screen pill ("one-handed · off") became a two-segment picker — TWO THUMBS / ONE THUMB — so the mode reads as a choice between equals rather than a toggle off a default. Panel toggle still mirrors it.
- **Rare coins (v16) — the LEGO blue stud.** User's ask; it is the canonical case of both bell-theory halves (variable magnitude + cue-before-reward). Two tiers because the LEGO magic is the tier above the one you thought was rare: **blue** = 25 coins, ~1 row in 50 (a few per run); **purple** = 100, ~1 in 400 (once every few runs). *(Odds raised on 2026-09-23 to 1/30 and 1/250; see the W24 entry below.)* Rolled per row, one lane, placed 28–42 % of lane width *off* the gap line so taking it means leaving the safe line and getting back — the risk is what makes the grab earned. Both chime on screen entry (two- / three-note rising arp) and carry a rotating four-point glint. Pickup: blue = flash, 60 px ring, 18 sparks, three-note arp; purple = bigger everything, 130 px white outer ring, 0.35 s slow motion, five-note run. Coins now also feed score at 2 dist per coin so a purple is +200 distance, not a vanity number. Colors chosen away from the default sky-blue thumb (#3d7bff electric, #b04bff purple).
- **Mobile pass (v17).** Touch targets to ≥42 px: switches 46×27, slider inputs 32 px tall with a 4 px visible track and 22 px thumb, seg/select/file/mode buttons 42 px, close 44 px, reset 44 px. Settings sheet: scrim behind it (tap outside to close; blocks taps reaching the field), drag-handle pill on mobile, `overscroll-behavior: contain`, safe-area bottom padding, notes trimmed to one line each. Opening settings mid-run **pauses**; closing gives 0.8 s grace. Landscape on a touch device with a short viewport shows "turn your phone upright" and pauses. Body: no overscroll bounce, `touch-action: manipulation` (kills double-tap zoom), no long-press callout, no text selection. After a crash, a held thumb that *moves* now restarts (a thumb that never lifted never fires pointerdown). Reset is two-tap with a 3 s arm window and **keeps the high score** — settings are preferences, best is earned.
- **Desktop port via one-thumb (v18).** User's observation: one-thumb is the mouse game. It is also the *only* desktop game — one mouse is one pointer, so two-thumb cannot start there, and a desktop visitor on the old default clicked into nothing. Now: first visit on a mouse device (`hover:hover`, `pointer:fine`, no touch) defaults to one thumb, never overriding a saved choice. Mouse is **sticky** — one click starts, the orb follows with no button held, only leaving the field lets go, and re-entering mid-run re-acquires without a click. A press on an already-bound pointer after death restarts (so click-to-restart works with a sticky mouse); the move-to-restart from v17 is touch-only so a mouse twitch doesn't skip the death screen. OS cursor hidden over the field during a run. On windows ≥700 px the app is a centred 520 px column — a monitor-wide lane is a different, easier game. CTA copy reads "click to start" / "click to run again" on mouse devices; the two-thumb picker gets a "needs a touchscreen" tooltip there.

- **Fonts self-hosted (W03, 2026-09-23).** The three Google Fonts `<link>`s are gone from `index.html`. `src/fonts/` holds the exact latin woff2 files fonts.gstatic.com served for the old request with an iPhone Safari UA (Sora v17 as one variable file, wght 100-800, 25,240 B; IBM Plex Mono v20 400 at 10,052 B and 500 at 10,060 B) plus `OFL.txt` with both copyright notices; `npm run fonts:check` pins their sha256 so a re-subsetted file cannot drift the title metrics silently. `@font-face` in `styles.css` uses `font-display:swap` and Google's latin `unicode-range` verbatim, so the HUD arrows keep falling back to the system font exactly as before; Sora is one face with `font-weight:400 700` (no separate 600 face: the range covers it, and a synthetic face would change HUD text). The fetch through the sandbox proxy worked, so the Fontsource fallback was not needed. Effect: zero network requests at startup, no device IP to Google (the copy agent's pre-ship finding 1), and the harness no longer logs the proxy's `ERR_TOO_MANY_RETRIES` on the stylesheet.
- **Canvas backing store capped at DPR 2 (W06, 2026-09-23).** `resize()` in `render.js` sets `view.dpr = min(2, devicePixelRatio)` and keeps the true ratio in `view.realDpr`; the cap lives inside `resize()` so the window resize handler cannot re-raise it. A 3x phone was rasterising 2.25x the pixels of a 2x one (1170x2532 vs 780x1688 for the same field) for 1 px lines and small text. `shadowBlur` is applied in store pixels, so the orb glow is scaled by `dpr/realDpr` to keep its on-screen size on 3x phones (the same rule applies to any later blur set from a CSS-unit value, W15's halo sprite included). No runtime governor and no 1.5 step-down: both verifiers saw a fractional dpr shimmer 1 px grid lines and pop mid-run. **Accepted trade:** 1 px lines and canvas text are slightly softer on DPR-3 phones (upscaled 1.5x by the compositor); the DOM HUD is unaffected.
- **Centre seam as a DOM layer (W04, 2026-09-23).** The seam is `#seamEl`, an 80 px white gradient band positioned under the canvas (`#seamClip` before `<canvas>` in `index.html`), and `draw()` writes only its opacity, and only when the value moves by more than 0.003; the per-frame `createLinearGradient` + full-height `fillRect` are gone. The tank fill column stays on the canvas. The seam is now off in one-thumb mode (one lane, nothing to divide: the harness's visual finding) and on the death screen, where it washed out the CTA. Measured two-thumb 20 s at 6x, 3-run medians back to back: p50 43.3 / p95 65.2 -> 26.8 / 56.3 ms.
- **Camera as a CSS transform (W05, 2026-09-23).** Shake and sway no longer go through `ctx2d.translate/rotate` (which re-rasterised the whole field): they are one transform string on the canvas and the seam, written only when it changes, with `transform-origin` at the element centre so it equals the old matrix exactly; `Math.random` is still called twice per shaking frame so the spawn RNG order is unchanged. Input maps thumbs in **unswayed** coordinates (pointer rects read from the wrap, handlers also on the wrap for the strip the canvas slid away from, mouse pointerout inside the wrap does not release), verified to 0.00 px on swayed frames. Measured 3-run medians: p50 27.4 / p95 53.5 -> 25.6 / 46.9 ms.

- **One-thumb pump multiplier (W20, 2026-09-23).** The harness finding above (one-thumb tank never past 22 in 12 s) is closed with `ONE_HAND_PUMP = 3.0`, a multiplicative factor on each registered stroke in one-hand mode: one thumb registers half the strokes and never earns the 1.8× bilateral bonus, so 3.6 would be exact two-thumb parity and 1.8 the bilateral bonus alone. Measured on the balance rig (60 s, casual 2.9 strokes/s): one-thumb fill median 1.65 s, 9.5 boosts/min (base: 0 boosts, max charge 23 %); frantic one-thumb (4.5 strokes/s) 0.90 s vs two-thumb frantic 0.83 s, so one hand cannot out-pump two; two-thumb is bit-identical (fill 1.58 s vs base 1.62 s). `CHARGE_DECAY` stays the same in both modes. - **Pause menu (W25, 2026-09-23).** Before this the only pauses were side effects (settings sheet, tab hidden, landscape) and every one of them auto-resumed, so there was no way to stop a run on purpose or to come back to it deliberately. Now: a 44 px pause button (`#pauseBtn`, first in the top-bar tools, shown only mid-run and never while dying or paused; the sound and gear buttons also went 36 → 44 px per the v17 target rule), a PAUSED card (`#overlayPause`, `.dead-block` layout with dist/coins/combo, a dimmed `rgba(11,13,18,.55)` backdrop so it reads over barriers) with three 44 px actions: settings (the sheet opens over the card and closing it returns to the card, not the run), restart, title (`quitToTitle`: field cleared, orbs re-centred, title overlay back). Resume is the thumbs, not a button: `game.pausedBy = "user"` marks a deliberate pause and the three side-effect resumes (tab return, `closePanel`, `checkOrientation`) skip it; every press on the field goes through `tryResume()`, which swallows presses for 300 ms after the pause (the tap that reached the button must not also resume) and then resumes once every lane's thumb is down. Resume gives 1.2 s of frozen-world grace with a 3-2-1 count (`game.countdown`, drawn directly by `draw()` rather than through `game.texts`, whose 5-entry cap would evict it under a burst of pass labels). Auto pause: two-thumb touch only, both thumbs off the glass for 1 s → `pauseRun()`, behind `state.autoPause` (default true, persisted, "Auto pause" switch under Feel); a sticky mouse lifts on every click and one-thumb lifts to reach the buttons, so neither qualifies. Audio ducks to a quarter behind the card (`audio.duck`) instead of suspending, so the bed still says the game is alive. Measured (`test/scratch-w25-pause.mjs`, 20 checks, all passing on the debug build): button hidden at title and 44×44 mid-run; a button pause freezes `world.time`/dist over 500 ms; a press 50 ms after the pause leaves it paused, one 450 ms after resumes with grace 1.17 and "3" on the canvas 60 ms later; dist unchanged at +1.0 s (grace 0.07) and moving at +1.6 s; restart → RUN at dist 0; settings-from-pause returns to the card; a faked hide/show keeps the pause; quit → title; both thumbs lifted → running at 0.6 s, paused by "user" at 1.3 s, resumed by both thumbs down; sticky mouse pauses via the button, re-entering the field re-acquires the orb without resuming, a click resumes. Zero page errors, zero frame errors in both scenarios. Harness (12 s at 6× CPU, two-thumb, 3 reps, base and patched pages built and run back to back on the shared box): base median p50 34.5 / p95 60.7 ms, patched p50 32.5 / p95 60.2 ms, 0 errors either side, i.e. no measurable cost (the pause code runs only on a press or a lift).
